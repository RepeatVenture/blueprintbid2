# Architecture

BlueprintBid uses Next.js 16 App Router, React 19, TypeScript 6, ordinary accessible controls and CSS, decimal.js, Supabase Auth/Postgres/Storage, Stripe-hosted billing, pdf-lib and PDF.js. Exact dependency versions are locked in package-lock.json. See ADR 0001 and 0002.

The public site, login, demo and hosted workspace share the same origin. The browser-local demo is explicitly synthetic and unauthenticated. Hosted API routes validate input and verify the Supabase user; queries use that user's session, so Postgres RLS remains effective. No interactive route uses an administrative database key.

Domains:
- `src/lib/model.ts`: runtime-validated project aggregate.
- `estimate.ts`: fixed-precision cost engine and customer projection.
- `commercial.ts`: allowances, alternates, vendor quotes and risks.
- `documents.ts`, `native-pdf.ts`: extraction contract and native-text provider.
- `pdf.ts`: customer-only PDF rendering.
- `server.ts`, `http.ts`: session verification, origin checks and bounded bodies.
- `src/app/api`: hosted project/catalog/document/invitation/billing services.
- `supabase/migrations`: relational tenant boundaries, membership, immutable versions, audit and billing state.

Project aggregates are JSONB inside a relational tenant boundary, with an optimistic revision counter. This allows the manual estimate to evolve without a migration for every new field. It is not a final analytical warehouse: reporting by operation, granular collaborative edits and large aggregate limits require normalized estimate tables later. A generated JSON schema subset validates project aggregates in Postgres as well as Zod in the application. Numeric refinements and identity checks execute before audit. New issued snapshots are regenerated by a deterministic Postgres numeric projection with parity tests against decimal.js. Auxiliary catalog/document writes and actual hosted grants still need integration review.

No external AI, analytics or error-monitoring vendor is installed. No email is sent by application code. Supabase sends authentication confirmation mail once configured. Invitation codes are shared manually by the owner. Document processing currently runs synchronously with page/size/time limits and a two-minute claim lease. A durable isolated queue is a launch requirement for untrusted large PDFs.

Official references: [Next.js installation](https://nextjs.org/docs/app/getting-started/installation), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Next.js self-hosting](https://nextjs.org/docs/app/guides/self-hosting).
